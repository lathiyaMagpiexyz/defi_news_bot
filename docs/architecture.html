Key Design Patterns

  • Event-Bus Pattern: Central EventBus (TypedEventEmitter) connects all components
  • Singleton Pattern: Config, Database, CollectorManager are singletons
  • Polling-Based Collection: Fixed interval data collection using setInterval()
  • Pipeline Architecture: Raw Data → Processing → Filtering → Alerting

Tech Stack

TypeScript Node.js SQLite (better-sqlite3) Telegraf Axios Zod p-queue

🚀 Startup Sequence

The application initializes components in a specific order to ensure dependencies are ready before dependent services start.

Initialization Order

  1. Configuration - Load YAML + environment variables
  2. Database - Run migrations, enable WAL mode
  3. SignalProcessor - Subscribe to collector events
  4. AlertManager - Subscribe to alert events
  5. TelegramBot - Start polling, setup commands
  6. Collectors - Start all in parallel

Scoring Weights

Score = (primaryMatches × 10) + (secondaryMatches × 5) + (hashtagMatches × 3) + (isPriorityAccount ? 20 : 0) + (retweets > 100 ? 5 : 0) + (likes > 500 ? 5 : 0) - (negativeMatches × 50)

🗄️ Database Schema

SQLite database with WAL mode for concurrent reads. All data is persisted for history and deduplication.

Key Indices

  • idx_alerts_dedup on alerts.deduplication_key - Fast duplicate checking
